# Smoke test: skeleton (OPA-8)

Proves that one plugin can ship a bar widget, an overlay and a service together, and that the three talk to each other.

## Prerequisites

1. From a checkout of the branch under test, install that checkout: `omarchy plugin add "$PWD" --enable`. It clones the checkout's current commit and puts the widget on the bar. (`make install` clones `main` from GitHub, so it does not test an unmerged branch.)
2. Restart the shell: `omarchy restart shell`.

## skeleton

1. Look at the bar. Expected: a key icon appears on the right of the bar.
2. Click the icon. Expected: the overlay opens with a centered card. Press Esc. Expected: the overlay closes.
3. Open the overlay again and click outside the card. Expected: the overlay closes. Clicking inside the card does nothing.
4. Run `omarchy-shell omapass toggle`. Expected: the overlay opens. Run it again. Expected: it closes. Repeat this right after a restart, before ever clicking the icon. Expected: same behavior, because the service owns the IPC target.
5. With the overlay open, read the card. Expected: it shows "service ok", not "no service".
6. Check the logs for QML errors: `journalctl --user -b -t omarchy-shell --since "-10 min" | grep -i -E "omapass|qml|warn|error"` (the shell logs to the journal under the `omarchy-shell` tag). Expected: no QML errors or warnings that name this plugin's files. A service load failure prints "service plugin load failed for elvisgastelum.omapass".

## Remove afterwards

1. `make uninstall` (runs `omarchy plugin remove elvisgastelum.omapass`). Expected: the plugin is removed.
2. `omarchy restart shell`. Expected: the bar icon is gone and `omarchy-shell omapass toggle` no longer opens anything.

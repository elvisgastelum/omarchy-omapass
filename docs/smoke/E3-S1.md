# Smoke test: cache and refresh (OPA-15)

Proves that the service keeps item metadata in memory, fills it in the background the first time the overlay opens, refreshes it when the overlay opens on a stale cache or on request, and never prints item details in its status output.

## Prerequisites

1. From a checkout of the branch under test, install that checkout: `omarchy plugin add "$PWD" --enable`. It clones the checkout's current commit and puts the widget on the bar.
2. Restart the shell: `omarchy restart shell`.
3. A signed-in `pass-cli` 2.7.1 or newer, with at least one vault that has items.

Status command used below: `omarchy-shell omapass cacheInfo`. It prints one JSON line with only these fields: `state`, `items` (count), `vaults` (count), `failedVaults` (count), `error`, `refreshing`, `calls` (running helper processes), and `ageSeconds` (null until a refresh fully succeeded).

## refresh

1. Right after `omarchy restart shell`, run `omarchy-shell omapass cacheInfo`. Expected: `state` is "loading", `items` is 0, and `ageSeconds` is null.
2. Open the overlay (click the icon, or run `omarchy-shell omapass open`). Wait a few seconds, then run `omarchy-shell omapass cacheInfo`. Expected: `state` is "ready", `items` is greater than 0, and `calls` is 0.
3. Close the overlay (`omarchy-shell omapass close`), then open it again within 120 seconds. Run `omarchy-shell omapass cacheInfo`. Expected: `ageSeconds` keeps growing from the earlier value, which shows that opening did not start a refresh.
4. Wait until more than 120 seconds have passed since the last refresh, then open the overlay again and run `omarchy-shell omapass cacheInfo`. Expected: `refreshing` is true for a few seconds; once it is false, `ageSeconds` is back near 0.
5. Run `omarchy-shell omapass refresh`, then immediately run `omarchy-shell omapass cacheInfo`. Expected: `refreshing` is true for a short time. Run it again after a few seconds. Expected: `refreshing` is false and `ageSeconds` is back near 0.
6. Read the whole `cacheInfo` output from steps 1 to 5. Expected: it contains no item titles, usernames or vault names. Only the listed fields appear.

## hidden vaults

1. List the vaults with their share ids: `bash bin/omapass-helper vaults | jq -r '.vaults[] | "\(.share_id)\t\(.name)"'`. Note the counts from `omarchy-shell omapass cacheInfo` first, so you can compare them later.
2. Back up `~/.config/omarchy/shell.json` before you edit it.
3. In `~/.config/omarchy/shell.json`, add `"hiddenVaults": ["<share_id>"]` to the `elvisgastelum.omapass` entry, using one share id from step 1, and save. Without running `refresh`, run `omarchy-shell omapass cacheInfo`. Expected: `vaults` and `items` are lower than before.
4. Remove the `hiddenVaults` key from the same entry and save. Expected: a refresh starts by itself, and after a few seconds `vaults` and `items` are back to the earlier counts.
5. In the same entry, set `"refreshMaxAgeSeconds": 10` and save. Run `omarchy-shell omapass refresh`, wait until `refreshing` is false, close the overlay, then open it after 15 seconds and run `omarchy-shell omapass cacheInfo`. Expected: `refreshing` is true, which shows that the reopen triggered a refresh.
6. Restore the backup copy of `~/.config/omarchy/shell.json`.

If `cacheInfo` shows `state` "loading" with 0 items right after a save, the shell read a half-written `shell.json`, fell back to its defaults and recreated the service. Run `omarchy-shell omapass refresh` and continue.

## failed refresh keeps the cache (optional)

1. With the cache loaded (`items` greater than 0), disconnect the network. Run `omarchy-shell omapass refresh`, then `omarchy-shell omapass cacheInfo`. Expected: `items` is the same as before, and `failedVaults` is greater than 0 or `error` is set.
2. Reconnect the network. Close and reopen the overlay, then run `omarchy-shell omapass cacheInfo`. Expected: `failedVaults` is 0, `error` is cleared, and `items` is greater than 0 again.

## logs

1. Check the logs: `journalctl --user -b -t omarchy-shell --since "-10 min" | grep -i -E "omapass|qml|warn|error"`. Expected: no QML errors or warnings that name this plugin's files.

Notes:
- If the 120 s backstop kills a helper process, its `pass-cli` child may keep running until the child's own timeout. A short delay in `calls` going back to 0 after that is expected.
- Lock and logout steps are in E3-S2.

## Remove afterwards

1. `make uninstall` (runs `omarchy plugin remove elvisgastelum.omapass`). Expected: the plugin is removed.
2. `omarchy restart shell`. Expected: the bar icon is gone and `omarchy-shell omapass cacheInfo` no longer returns cache data.
